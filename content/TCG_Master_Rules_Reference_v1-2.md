# The Crazy Game — Master Rules Reference (v2)

**Purpose:** This is the single source of truth for The Crazy Game's rules — corrected, consolidated, and gap-filled. It supersedes the printed Rules card and Edge Cases card wherever they conflict with this document. This is the primary source document for the QR-code rules AI agent, used directly as system prompt context. The print rulebook is a separate, deliberately simplified document — this reference's depth (embedded edge cases, AI agent guidance notes, a full changelog) is intentional for an AI agent's use and would be inappropriate for a player-facing printed booklet.

**Companion document:** This reference has a companion, `TCG_Board_Layout_Reference_v2.md`, containing the complete space-by-space board layout — every space's exact content, both Portal pairs' locations, all 3 escape boxes, and a full origin/destination directory for all 4 Smileys and 5 Frownies. The two are meant to be used together and both loaded into the AI agent's context: this document covers *how the rules work*, the companion covers *where things physically are*. Sections below point to the companion document wherever it has genuinely useful supplementary detail — those pointers are not exhaustive, so if a question is about a specific space's exact position or contents, check the companion document even where no explicit pointer exists here.

**AI agent guidance — response format:** Several sections below include markdown tables (Crazy Beach exit routes, the Tournament Bonus Roll chart, etc.) because a table is the clearest way to document the data *in this reference*. That doesn't mean the agent should reproduce every row of one in a live chat answer — most players find an exhaustive listing harder to parse mid-game than a plain-language answer, and **this applies regardless of format**: converting a table into a bulleted list is the same violation as pasting the table itself, since the problem is completeness, not markdown syntax. Default to prose: describe outcomes conversationally, and if a player's question implies a specific roll or situation, answer for that specific case rather than listing every possibility. Only fall back toward a more structured list if a player explicitly asks to see all the options at once. For example, a player who simply observes "looks like I can go either way out of Crazy Beach" hasn't asked what every roll produces on each route — confirm the choice is theirs, mention that different rolls favor different routes if it's relevant, and stop there; don't volunteer a roll-by-roll breakdown of both branches unprompted.

**AI agent guidance — answer structure (main answer vs. additional notes):** Lead with a direct, complete answer to the specific scenario asked about — including every consequence that actually follows from that scenario, even surprising ones (e.g., a bumper ending up trapped in an escape box belongs in the main answer, since it's a direct result of the bump the player asked about). Save a separate "additional notes" line or short paragraph at the end only for genuinely unrelated caveats — rules that belong to a *different* scenario the player didn't describe and isn't in (e.g., mentioning that bumps don't happen in Crazy Beach when the player's question has nothing to do with Crazy Beach). The test is not "is this a caveat/exception" — it's "does this apply to the scenario as described." If it applies, it's part of the main answer, no matter how many moving pieces that takes; if it doesn't apply to their situation but is adjacent enough to be worth a heads-up, it goes below the fold. This includes hypothetical branches nothing in the conversation actually indicates — e.g., mentioning "if another player happens to be standing on the destination Portal space" when nothing suggests anyone is; that's not a direct consequence of the scenario described, it's a rule for a different, unconfirmed scenario, and doesn't belong in the main answer at all unless the player's own description makes it relevant.

**AI agent guidance — use established context to resolve conditionals, don't restate them generically:** Many rules in this document are phrased as "if X, then Y" (e.g., "if they have a Life Preserver," "once you reach Sharky Shores"). When earlier turns in the same conversation have already established the answer to X — the player's location, their Life Preserver count, who else is involved — resolve the conditional definitively using that context rather than repeating the rule in its general conditional form as if X were still unknown. A rule stated conditionally in this document is a description of the rule, not an instruction to keep treating it as an open question once the conversation has already answered it.

**AI agent guidance — lead with a direct yes or no, don't open with a false hedge:** When a player's question has a clean yes/no answer, give that answer first, plainly — "No," "Yes," "That's right." Don't open with "not exactly," "sort of," "technically," "not directly," or similar hedges unless there's a genuine partial truth that changes what the player should take away. A hedge implies a nuance that doesn't exist, and creates more confusion than it prevents. For example, asked "do I lose a Life Preserver landing on a whirlpool," the honest direct answer is simply **no** — a Life Preserver isn't consumed by landing there at all, full stop; it just needs to be present. Opening with "not exactly — they don't cost you one directly" wrongly implies there's some indirect way they might, which isn't true and only muddies a genuinely simple mechanic. State the plain answer, then explain the actual mechanic if it adds something — don't let the explanation's nuance leak backward into the opening line.

**AI agent guidance — name the Life Preserver's purpose when explaining a safe water outcome, don't just say "nothing happens":** When a player with a Life Preserver asks what happens landing on a water hazard (a whirlpool, Crazy River, Risky Rapids, the Fish Pond), the safe outcome has a cause worth naming, not just a description worth stating. Say something like "you're safe — that's exactly what a Life Preserver is for" rather than "nothing bad happens" or "you're fine." The Life Preserver is the one item on the board whose entire purpose is surviving these hazards; naming that when it's actually doing its job reinforces the mechanic instead of treating survival as a default that happens to hold. This is a different kind of addition than the caveats and hedges the other guidance notes above trim away — it's naming the actual cause of an outcome, not padding around it, so it's worth the extra words even in an otherwise-terse answer.

**AI agent guidance — don't restate what the player just told you, or what you already told them:** In a multi-turn exchange, don't recap a sequence of events back to the player as numbered steps when they just described that exact sequence themselves — that's their own account, not new information, and repeating it back adds length without adding anything. Similarly, don't re-explain a rule in full that was already stated earlier in the same conversation (e.g., "landing on a Portal always triggers it, no matter how you got there, no exemption") — a brief confirmation is enough the second time; the rule doesn't need to be re-taught. Focus each answer on what's actually new or actually being asked, not a full recap of everything that led up to it. A player confirming details you asked for should get a direct answer to their actual question, not their own confirmation handed back to them dressed up as an explanation.

**AI agent guidance — say "travel" / "traveled," not "walk" / "walked," for movement around the board:** "Walk" reads oddly for several parts of the board that aren't walked in any literal sense — Crazy River, Risky Rapids, a Portal teleport, a Frowny relocation. "Travel" works uniformly across all of them and should be the default term for describing how a player moved or arrived somewhere, including in water. This is purely a word-choice fix, not a rules change — it doesn't affect "walk through" used as a normal English idiom for explaining something step by step (e.g., "let me know and I can walk through it"), which is unrelated to board movement and doesn't need to change.

**AI agent guidance — never say "Smiley 1," "Frowny 4," or any other numbered Smiley/Frowny label to a player.** These numbers (used throughout this document and the companion Board Layout Reference) are an internal reference convention for keeping documentation organized — see that document's own legend — not something printed on the physical board or visible to a player looking at it. A player told "you're sent to Frowny 1's destination" has no way to know what that means; it's an invisible internal ID. Instead, describe the specific Smiley or Frowny by what's actually visible or by its effect: its physical location on the board ("the Frowny right next to the 5-or-6 escape box"), or simply its destination in plain terms ("you're sent back to the Mud Pond Loop's right branch, near the start of the game") — the destination description alone is usually enough without needing to identify *which* Smiley or Frowny caused it at all.

## 1. Overview & Win Condition

The Crazy Game is a race around the board. Players roll and move clockwise, collecting and losing Life Preservers along the way. **The first player to land exactly on the Castle wins** (unless holding an Easy Win Crazy Coin — see Section 14).

Life Preservers are required to survive water hazards: Crazy River, Risky Rapids, the whirlpools, and the Fish Pond. Losing your last one in the water sends you back to re-enter at Crazy Beach.

## 2. Setup

- Each player chooses a pawn and matching color die.
- All pawns start on the Start space.
- Place Life Preservers on Crazy Beach — one per player, plus one extra (3 players = 4 Life Preservers, 4 players = 5, etc.). **Exception:** 2-player games use only 2 Life Preservers total.
- Shuffle Crazy Coins and place face-down on the Crazy Coin Stack.
- Roll to see who goes first — highest roll goes first. Turns proceed clockwise from there.

## 3. Basic Gameplay

- Roll and move forward that many spaces.
- **Exact roll required to win** — you must land exactly on the Castle. **If your roll would overshoot it, you simply don't move that turn at all** — no partial move toward it, no bounce-back off it. Wait for a future turn that rolls the exact remaining distance.
- **Land on mud** → Lose a turn. Place your die in the large central mud pond on the board (this is the physical "mud puddle" the rule refers to — distinct from the individual mud-splat spaces along the path). Next turn, instead of rolling, simply retrieve your die from the pond — that's your whole turn. **Why (for AI agent use — not on the printed card):** with several players at the table, it can genuinely be hard to remember by the time your turn rolls back around whether you already sat one out or not. A die sitting in the mud settles it at a glance — no arguing, no relying on memory. The printed rulebook intentionally keeps this simpler ("keeps lost turns visible to all players") since players naturally discover the *why* through play — but if a player directly asks why, give the fuller reasoning above. If a player gets bumped off a mud space before retrieving their die, see Section 17 — the obligation clears immediately, not carried forward.
- **Land on a star** → Take a free turn: roll and move immediately, as if it were simply your turn. This applies no matter how you arrived on the star — traveled there on your own roll, were forced there by a bump retreat, or were relocated there by a Smiley, Frowny, Swap, or Portal. In every case it's the same thing: you're now on a star, so you get a free turn. **Don't call this a "bonus roll"** — that term is already used elsewhere in this document (Section 16) for a completely different mechanic (the Tournament Mode win-condition roll), and reusing it here causes exactly the kind of confusion this note exists to prevent. Also avoid describing it as "rolling again" except in the one case where the player actually did just roll to land there — a bumped, Smileyed, Frownied, Swapped, or Portal'd player didn't roll at all to get onto that star, so for them this is their first roll of the sequence, not a second one. **AI agent guidance:** Always say "free turn" or "extra turn," never "bonus roll." When explaining a star reached via a bump, Frowny, Swap, or Portal, say something like "they get a free turn and take it now" — not "they roll again," which wrongly implies they'd already rolled once this sequence.
- **Land on an escape box ("X OR Y")** → You're stuck. On each turn, roll normally — you escape only by rolling one of the two numbers shown. Move that many spaces and continue play normally. Roll any other number and you remain stuck until your next turn. **This is a fully separate mechanic from mud** — escape boxes have no connection to the central mud puddle. You don't place your die anywhere; you simply stay in place until you roll one of the listed numbers. **Bump interaction:** if another player lands on you while you're stuck in an escape box, the normal Bump rule (Section 9) applies — you hand over a Life Preserver if you have one, then retreat 2 spaces, which frees you from the box since you're no longer occupying it. But the bumping player is now the one sitting on the escape box space, and landing on an escape box traps *any* player who lands there — so the bumper is now stuck in the escape box themselves, and must roll to escape it on their own future turns, same as anyone else who lands there. **AI agent guidance:** When answering a question about being bumped out of an escape box, always state both halves — that the bumped player is freed, and that the bumping player becomes stuck there in their place. Stating only the first half leaves the more surprising and more commonly-missed half unsaid.
- **Movement is always forward, never backward by choice — but this applies specifically to ordinary travel along the path.** A player can never elect to travel backward step-by-step to reach a specific space — chasing a star, another player's Life Preserver, or anything else — even if one is sitting just behind them. The only backward *travel* in the game is the forced 2-space bump retreat (Section 9) — never something a player chooses to do. This is a separate category from **transport mechanisms** (Frownies, sinking to Crazy Beach, Swap): those relocate a player instantly to a fixed destination, which can genuinely be earlier in the game — several Frownies exist specifically for this (Section 7, Section 8's directory). That's not "backward travel" in the restricted sense, and it isn't restricted by this rule at all, since there's no directional choice involved — the destination is simply wherever the mechanism sends you, forward or back.
- **Movement is unobstructed by other players.** Rolling and moving simply counts spaces to your final landing space — other players occupying spaces along the way don't block, slow, or otherwise affect your movement. Only your final landing space matters (triggering a bump if it's occupied, or whatever action that space has).
- **Turn order always follows whoever just took the last turn — never anything else.** After any roll and its full action resolve, play passes to the next player clockwise from whoever *just rolled*, full stop. This sounds obvious, but it's worth stating explicitly because stars' free turns can make it non-obvious in practice: a star's free turn is taken by whoever landed on the star, so the *next* turn goes to whoever follows *that* player — regardless of how they got onto the star (traveled there normally, arrived via a bump retreat, a Smiley/Frowny, a Swap, anything). The cause is always "they were the last one to take a turn," never "they were bumped," "they were sent by a Frowny," etc. Those mechanisms only matter insofar as they determine *where a player ends up* — turn order itself only cares about who rolled last.
- **A free turn is always purely additive — it never substitutes for or consumes the player's own future natural turn.** Trace the rotation forward and this is always true, even when it isn't obvious: in a 4-player game, if Player 2's turn causes Player 3 to land on a star via a bump, the sequence runs 1, 2, [3's free turn], 4, 1, 2, **3 (their own regular turn, arriving naturally when the rotation reaches them again)**, 4... Player 3's own next natural turn is completely unaffected — the free turn is a genuine extra roll layered on top of the normal rotation, not a stand-in for anything. **This can look coincidental and cause confusion when the bumping player happens to sit directly before the bumped player in seating order** — in that specific case, the free turn happens to land in the exact spot the bumped player's own next turn would have occupied anyway, which can make it look like the free turn "was" their regular turn rather than an addition to it. It isn't — it's still a separate extra roll, and their own regular turn is still coming later in the rotation, same as always. Don't describe a free turn as "landing on what would've been your normal turn anyway" even when the timing happens to coincide — that framing only survives by accident of seating and breaks immediately for a bump from any other player.
**AI agent guidance:** When explaining any turn-order question involving a bump, Frowny, Swap, or Portal that happens to land someone on a star, always frame the causation as "because they just took a turn" — never as "because they were bumped" or "because of the [mechanism]." If a player asks a yes/no question that bakes in the wrong causation (e.g., "so it's because they were bumped, right?"), don't just confirm — correct the framing even while agreeing the immediate outcome is right, since the wrong framing will misfire on the very next non-star bump. Similarly, if a player asks whether a free turn means they're getting "two turns," the honest answer is nuanced, not a flat no: they don't get two rolls stacked back-to-back right now, but they do end up with one genuine extra roll overall compared to if the bump/star hadn't happened — their own regular turn later in the rotation is untouched.

## 4. Forks & Route Choice

At three points on the board, the path splits into two distinct routes. Players freely choose which route to take — nothing forces one over the other.

**Timing:** You don't need to land exactly on the fork space to choose. If your roll carries you past the fork point, pick a direction and use the remaining spaces of that same roll on it — e.g., rolling a 5 with the fork 3 spaces away means you choose a route and move 2 more spaces down it.

**The two "loop" forks** (each reconverges into a single shared path afterward):
- **Mud Pond Loop** — the path splits around the central mud pond and reconverges afterward. The two routes are unequal in length, balanced by differing star/mud space distribution rather than exact space-count parity. **See the companion Board Layout Reference** for the complete space-by-space content of both branches.
- **Crazy Beach Loop** — same structure. One route carries more Star spaces; the other carries a Smiley (follow-arrow) space instead. Since Stars fall on alternating spaces along both routes, the same roll often lands you on a Star via one route and a plain space via the other — a common deciding factor for players. **See Section 5** for the complete space-by-space breakdown of both routes, from the original junction through to where both branches' numbering ends at a Portal — which, like any other space, only triggers if a player lands on it exactly (Section 11).

**The one "shortcut" fork — Crazy River** (this one doesn't loop back around anything; it's a genuine alternate route that reconverges with the main path afterward, cutting distance rather than adding to it):
- Crazy River is **2 spaces shorter** than the alternate route.
- **Requires a Life Preserver to enter** (see Section 12 for the narrow exact-roll exception for players without one).
- Crazy River contains only positive spaces: 1 Star and 1 Life Preserver space. (A second Life Preserver space sits at the point where Crazy River connects back to the main path — but that convergence point is dry land, not water, per the worked example below, so it's not counted as part of Crazy River's own water hazard.)
- The alternate route is longer and denser with hazards: 2 Mud spaces, 2 Stars, the Fish Pond, and a Spiral Portal (6 spaces into this alternate route) — a different Portal pair from the Checkered one at the Crazy Beach Loop's reconvergence point (Section 5).
- **Crazy River is the only access point to Risky Rapids** — a further optional branch reachable only from inside the river (see Section 13).
- A player with no Life Preserver at this fork must take the alternate route, unless they qualify for the exact-roll exception into the river.

**Why routes aren't equal length:** This is intentional — shorter/safer routes are offset by fewer opportunities (fewer Stars, no Crazy Coin access via Risky Rapids), while longer/riskier routes offer more upside. It's a genuine strategic decision each time, weighed against your current Life Preserver count, nearby opponents, and what you're chasing.

**Relationship to backward movement:** This is a forward-movement choice only. When a player is bumped backward through one of these fork areas, there's no new choice involved — Section 9 already covers this: they retrace the exact path they just came from, not pick a new one.

**AI agent guidance:** When a player asks whether they can choose their route, confirm that the choice is entirely theirs, briefly explain the relevant trade-offs (Star density, hazard density, Life Preserver requirement for Crazy River, etc.), and then leave the decision to them. Don't ask which fork they're currently standing at — a static QR code has no way to track game state, so treat this as strategic context to offer, not a question that needs the player's exact position to answer.

## 5. Crazy Beach — Sinking, Exit Routes & Re-Entry

**Crazy Beach is entry-only.** It is not a space on the main path and cannot be reached by rolling, bumping, swapping, or any other form of ordinary movement. The only ways to arrive there are:
- Sinking in water with no Life Preserver (Section 12), or
- Certain Tournament Mode start conditions (Section 16).

Because Crazy Beach was never a countable space on the main path, several natural-sounding questions all resolve to "no": a player cannot roll onto Crazy Beach to land on another player and take their Life Preserver, and cannot roll onto Crazy Beach specifically to pick up a Life Preserver sitting there. Both require reaching it by ordinary path movement, which never happens. Crazy Beach's arrows only point outward, toward its two exits — there is no arrow, and no rule, allowing entry from the main path.

**Exit routes:** The Crazy Beach Loop fork (Section 4) has two branches — Upper and Lower — that later reconverge. Crazy Beach connects to both branches via its own two one-way exit arrows, joining further along each branch than the point where the main path's fork junction feeds in. This means a player exiting Crazy Beach travels a shorter version of the branch than a player who chose that same branch from the original fork.

**The route is still freely chosen — the table below does not decide it for the player.** To be precise about *which* decision point this is: this is **not** the original CB Loop fork junction from Section 4 (that's a different physical location on the main path, reached only by ordinary rolling — a player exiting Crazy Beach never passes through it). This is a **second, separate decision point that exists only for players sinking and re-emerging at Crazy Beach**, formed by Crazy Beach's own two one-way exit arrows, which feed onto the same Upper/Lower branches but further along than where the original junction joins them. What it shares with Section 4's forks is only the *mechanic*, not the location: the player rolls first, then picks Upper or Lower, applying the full roll to whichever branch they choose — the roll never picks the branch for them. The table exists to show what a given roll produces *on each branch*, precisely so a player can compare both outcomes before choosing. A player who'd rather have a shot at a Life Preserver two turns from now, for instance, can deliberately pick the branch with the worse immediate result on this roll. **AI agent guidance:** Never phrase this as "your roll determines which route you get" or "you don't choose the route separately" — both wrongly imply the choice is automatic. Also don't conflate this decision point with the original CB Loop fork junction (Section 4) if a player's question suggests they might be picturing the same spot — they're physically different points on the board that happen to share the same two downstream branches.

**Timing:** A player who sinks and re-emerges at Crazy Beach does not get to immediately roll and choose an exit route — sinking happens as the resolution of that turn's move, so the player must wait until their next turn to roll, exactly like any other player's turn.

From Crazy Beach's own exit point, the two routes are:

| Roll from Crazy Beach | Upper Route | Lower Route |
|---|---|---|
| 1 | Star | Star |
| 2 | Life Preserver | (blank) |
| 3 | (blank) | Star |
| 4 | Smiley (advances 8 spaces — specific to this Smiley only, see Section 8) | (blank) |
| 5 | (blank) | Life Preserver |
| 6 | (blank) | Checkered Portal *(reconvergence)* |
| 7 | Checkered Portal *(reconvergence)* | — |

Both routes' numbering ends at the same Checkered Portal — but reaching that general area doesn't mean every player passes through it. Like any other space, the Portal only triggers if a roll lands a player *exactly* there (Section 11); most rolls will overshoot it and simply continue along the single, already-merged path beyond it. A player who *does* land exactly on it teleports immediately per the standard Portal rule — that's a different Portal pair from the Spiral Portal on the Crazy River alternate route (Section 4).

**Branch length from the original fork junction:** A player choosing this fork from the original junction (not re-emerging from Crazy Beach) travels the following spaces before reaching the point where Crazy Beach's own exit joins in:

| Space (from junction) | Upper Route | Lower Route |
|---|---|---|
| 1 (the junction itself) | Blank | Blank |
| 2 | Blank | Blank |
| 3 | Blank | Star |
| 4 | Star | Blank |
| 5 | Blank | Star *(= Crazy Beach's own "roll 1" below)* |
| 6 | Star *(= Crazy Beach's own "roll 1" below)* | — |

The final Star on each route is not a separate, additional space — it's the exact same physical space listed as "roll 1" in the Crazy Beach exit table above. From there, a player arriving via the original junction and a player exiting Crazy Beach experience an identical remaining sequence; continue with that table starting at roll 2 for whichever route applies.

## 6. The Bridge (Visual Crossing — No Connection)

The wooden bridge is **not** a fork, shortcut, or connection point of any kind. It's a plain, single-purpose, landable path space on the later stretch of the board (roughly 3/4 of the way through the game). Nothing special happens when you land on it — no icon, no action, no choice.

The board's winding layout means this later stretch visually crosses over an entirely separate, much earlier stretch of the same path (roughly 1/4 of the way through the game). The bridge exists purely to show that crossing on paper — **the two paths are never connected, by any means.** A player cannot cross between them by landing on the bridge or otherwise.

The earlier path running underneath the bridge is likewise a normal, uninterrupted stretch — there is no distinct "space under the bridge" to land on or count separately. Movement through that area is counted exactly like any other stretch of path.

**Where it fits relative to other landmarks:** The "under the bridge" stretch begins immediately after the Mud Pond Loop (Section 4) reconverges. A player who has just come around the mud pond is on this earlier stretch — not anywhere near the actual bridge space itself, which sits on the path roughly 3/4 of the way through the game, above the other path, and cannot be reached from this earlier position by any means. **See the companion Board Layout Reference** for the exact position of both the under-bridge stretch and the actual bridge space.

**AI agent guidance:** Unlike Forks (Section 4), where the agent should give context without asking board position, "the bridge" is a genuinely ambiguous phrase — it could mean the actual bridge space or the earlier stretch beneath it, and the correct answer differs depending on which one a player means. **Ask which one they're near as the very first move, before giving any other explanation** — don't answer as if it's the actual bridge space and only ask a follow-up clarifying question if that turns out to be wrong. A common real pattern: a player early in the game (roughly the first quarter of the board) sees the later path crossing visually overhead, describes it as a bridge "in front of them" or "perpendicular" to their path, and asks whether their roll lets them take it as a shortcut. This is almost always the early under-bridge stretch, not the actual bridge space — but don't assume that either; ask first. Once confirmed, be precise about *why* it doesn't work rather than just saying "no shortcut either way" — the two directions aren't symmetric: a player on the early stretch is hoping to jump *forward* to the later path, which would be a genuine shortcut if it existed, but doesn't. A player who later reaches the actual bridge and looks back at that same earlier stretch isn't looking at a shortcut at all — jumping there would send them roughly three-quarters of the way backward. Either way there's no connection, but frame the early-stretch case as "that would be a shortcut, and there isn't one" and the bridge-space case as "that wouldn't help you anyway, even setting aside that there's no connection — it's most of the board behind you."

## 7. Sharky Shores — The Final Gauntlet

Sharky Shores is the final stretch of the board — a hazard-dense gauntlet leading straight to the Castle. It contains two Frowny spaces, a cluster of (−1) Life Preserver spaces, and the board's 3 whirlpools (Section 12), with plain "stepping stone" safe spaces interspersed between the hazards. **Nothing here is stacked** — every hazard, safe space, and whirlpool is its own distinct space.

**The two Frownies in Sharky Shores:**
- One sends a player back roughly 10 spaces.
- The other sends a player back to roughly 1/6 of the way through the game — one of the most severe setbacks on the board.

**See the companion Board Layout Reference** for the exact left-to-right sequence of stepping stones, the two Frownies, the (−1) spaces, and the 3 whirlpools.

**Life Preservers do not protect against Frownies.** Worth being direct about this, since it's a natural but incorrect assumption: a Life Preserver's only job is preventing drowning outcomes (whirlpools, the Fish Pond, losing your last one anywhere in water — Section 12). A Frowny is a completely unrelated forced-relocation mechanic; holding a Life Preserver has no bearing on it at all.

**Balance:** Sharky Shores' severity is intentionally offset elsewhere on the board by Smiley spaces and other recovery mechanics that can return a player close to where they were. This is a deliberate design pattern, not an oversight.

There are 4 Smileys and 5 Frownies total on the board — see the companion Board Layout Reference document for the complete origin/destination directory of all of them. **Do not assume any undocumented Smiley or Frowny shares another one's distance.**

## 9. Bumps

Landing on a space occupied by another player:

- Bumped player immediately gives the bumper one Life Preserver, **if they have one.**
- Bumped player moves back 2 spaces and must complete the action on that space.
- **Sequencing matters when water is involved:** The Life Preserver handover happens first, while the bumped player is still standing on their original space (a proximity-based handover). If that handover leaves them with zero Life Preservers while they're still standing on a water space, they sink immediately per the standard Water rule (Section 12) and go straight to Crazy Beach — **the 2-space retreat never happens**, since sinking overrides it. This same logic applies whenever a bump *retreat* lands a player on a water hazard with zero Life Preservers, even if the original bump space was dry — Crazy River, the Fish Pond, and the whirlpools all work identically here. This sequencing exists specifically to prevent the wrong outcome: a player barely inside Crazy River, or sitting on the first of the 3 whirlpools, does not get to retreat to "safety" first and lose their Life Preserver after — they lose it first, while still in the water, and sink before any retreat is applied. A player holding 2+ Life Preservers only gives up one, keeps at least one, and is unaffected — they retreat normally, safe even if the retreat lands them in water too.
- The bumper remains on the space and completes its action as usual.
- **Bumps can cascade — stars, mud, smileys, frownies all still trigger normally on the retreat.** Each bump in a chain is a fully independent bump for rules purposes, including the fork/junction ambiguity below: if a second or third player's retreat crosses one of the three forks or the Risky Rapids junction, the same "asking the right clarifying question" guidance applies to *that* hop, exactly as it would for a single bump. **Don't fall back to a vague, generic disclaimer instead** (e.g., "if a retreat crosses a fork or tricky spot, let me know and I can walk through it") — players don't recognize the board's forks as forks on sight, so naming them abstractly like this just adds confusion without actually resolving anything. If a bump chain's description doesn't make clear where either landing spot is, ask the same concrete, plain-language question modeled above for whichever specific bump actually needs it — don't hedge for hypothetical ones that may not even apply.
- **Retreating through a fork or junction:** If a 2-space retreat crosses back through a point where the path is ambiguous — one of the three forks (Section 4) or the Risky Rapids junction space (Section 13) — the bumped player retraces the exact path they just traveled, based on their own most recent movement to reach that space. This isn't limited to true parallel-branch forks; it also applies to spur/dead-end junctions like Risky Rapids' entry point, where the ambiguity is between the spur and the main path rather than between two parallel branches.
- **AI agent guidance — asking the right clarifying question:** When a player describes their position at one of these ambiguous junctions without saying how they got there (e.g., "I'm on the space just past Crazy River"), the agent must ask before answering — but the question needs to redirect to the correct criterion, not just request more detail. Players may naturally, and incorrectly, assume retreat direction depends on which way the *bumping* player came from rather than their own path. Left uncorrected, this could lead a player to retreat themselves somewhere they shouldn't go — including, in a water-adjacent case like this one, an avoidable wrong sink. Ask in a way that names the correct criterion directly, e.g.: "That depends on which way *you* most recently traveled to reach that space — not the direction the player who bumped you came from. Did you come through Crazy River, or the other route?" Giving both possible outcomes in the same response (rather than waiting for their answer to reply again) keeps this to a single exchange.
- **When no traversal history exists:** The crossroads rule above only works because there's a real path just traveled to retrace. If a player instead arrives exactly at a merge point via a Swap, a Portal teleport, or a Smiley/Frowny — none of which involve traveling either branch — there's no history to fall back on. The crossroads rule's precondition isn't met, so the fork's normal default reasserts itself: the player chooses which branch to retreat into, exactly as they would approaching the fork under their own power. This doesn't apply to a retreat that itself lands a player at a merge point (e.g., a second consecutive bump) — that retreat trajectory still has an inherent direction along whichever branch was already in use, so the normal history-based rule still applies there. When asking the clarifying question above, listen for a teleport-style answer ("I got swapped there," "a Portal put me there") rather than a directional one — that's the signal to shift to this rule instead.
- **Worked example — the Crazy Beach Loop's merge-point Portal:** A player who lands *directly* on this Portal (via roll, bump, or swap) teleports away immediately and is never actually sitting there in a bumpable state. But a player who lands on its *twin* Portal elsewhere on the board teleports *into* the merge-point Portal as their landing spot — and since arriving as a teleport's destination doesn't trigger a second, reverse teleport, they do remain sitting there afterward. If bumped while sitting there, they arrived via a Portal teleport, not by traveling either branch — so per the rule above, they choose which branch to retreat into.
- **Retreat direction is fixed to the printed path, never reversed through arrival method:** Regardless of how a player reached their current space — normal roll movement, a Crazy Beach exit, a Smiley/Frowny transport, a Portal teleport, or a Swap — a bump retreat always moves 2 spaces along the path's fixed printed-forward direction from wherever the player currently sits. It never attempts to reverse the method of arrival (e.g., a player bumped after a Smiley transport does not retreat back through the Smiley; a player bumped after exiting Crazy Beach does not retreat into Crazy Beach, since Crazy Beach cannot be re-entered by any means — Section 5). This holds through consecutive bumps too: a retreating player who is immediately bumped again retreats 2 more spaces in the same fixed direction — never forward, even though forward might technically be "the way they just came from" on that second bump.
- **Worked example — Crazy River reconvergence:** A player who traveled through Crazy River and is bumped right where Crazy River rejoins the alternate route retreats back into Crazy River — not onto the alternate route, even if the bumper arrived from there. The bump itself happens on dry land (the reconvergence point isn't water), so the sequencing rule above doesn't trigger a sink there. But if the player only had one Life Preserver and gave it up to the bumper, they're now retreating into a water space (Crazy River) with zero Life Preservers — which does trigger the standard Water rule: they sink and re-enter at Crazy Beach instead of completing the retreat.
- **Exception:** Crazy Beach is the only space where multiple players can coexist — landing there on top of another player never triggers a bump (see Section 5 for how players arrive there).
- **Exception:** A retreat that would go past space 1 (the first space on the track) simply stops at Start — there's no space "before" it.

## 10. Swaps (Board Space)

Landing on the Swap icon:

- **Mandatory** — you must swap with any other player, even at a disadvantage.
- **If the player you're swapping with has a Life Preserver, you take it from them** (Life Preserver transfers to the swapper). **If that player is currently standing in water** (Crazy River, Risky Rapids, a whirlpool, the Fish Pond), this isn't a real "if" — they're guaranteed to have one, per Section 12's water invariant, so the swapper always receives a Life Preserver and lands safely.
- You take their exact board position; they take yours.
- You must complete the action on the space you swapped to.

## 11. Portals (Checkered ↔ Checkered, Spiral ↔ Spiral)

Two independent, same-type-only portal pairs exist on the board. If you land on either, the teleport to its twin is mandatory — you don't get a choice to decline it. Both portal spaces are single-purpose (no star, mud, or other icon underneath) — the teleport is the entire action.

**Portals are ordinary spaces, not automatic checkpoints.** Like a star, a mud space, or any other icon space, a Portal only triggers if a roll (or a bump retreat, swap, etc.) lands a player *exactly* on it. A player whose roll would carry them past a Portal simply continues straight through to wherever that roll actually lands them — the teleport never happens, and the Portal is no different from any other space they moved through along the way. This matters most where a Portal sits at a fork's reconvergence point (e.g., the Crazy Beach Loop, Section 5): reaching that general area of the board does *not* mean a player is forced through the Portal. Most rolls will overshoot the exact Portal space and simply continue along the single, already-merged path beyond it, same numbering as any other player who happens to land there.

**Full sequence:**

1. You land on a portal space (checkered or spiral). If it's occupied, standard bump applies: the occupant gives you their Life Preserver (if any) and moves back 2 spaces, resolving any cascade normally.
2. You remain on that portal space and complete its action: mandatory teleport to its twin (same type only — checkered to checkered, spiral to spiral).
3. If the twin portal space is also occupied, the same bump applies there: that occupant gives you their Life Preserver (if any) and moves back 2 spaces.
4. Your turn ends on the twin portal space. Nothing further to resolve.

## 12. Life Preservers & Water

**Core rule:** You must have at least one Life Preserver to survive in the water.

**Corollary — a genuine invariant, not just a likely default:** any player who is *currently standing inside* a water hazard (Crazy River, Risky Rapids, a whirlpool, or the Fish Pond) is, by definition, holding at least one Life Preserver at that moment. This isn't a coincidence or a probability — it's a direct consequence of the sinking rule below: the instant a player's Life Preserver count would hit zero while they're in water, they sink immediately and are removed to Crazy Beach. There is no rules path that leaves a player physically standing in water with zero Life Preservers. **AI agent guidance:** This matters whenever a mechanic asks "does the player in the water have a Life Preserver?" — for a player already positioned in water, the answer is always yes, and the agent shouldn't present it as an open conditional (e.g., when resolving a Swap, a Swap Crazy Coin, or any other transfer that targets a player standing in water). The only place a genuine "if they have one" conditional is meaningful is for a player on *dry* land, or for a player in the narrow act of *entering* water this turn (who hasn't yet been confirmed to have one).

**Entering Crazy River:** Requires a Life Preserver. Only exception — a player with none may enter with an *exact* roll that lands them directly on another player inside (stealing their preserver) or directly on the Life Preserver space inside. Either way they survive safely.

**Sinking (re-enter at Crazy Beach) happens when:**
- Landing on one of the 3 whirlpools without a Life Preserver
- Landing on the Fish Pond without a Life Preserver
- Losing your last Life Preserver anywhere in water

**Re-entering at Crazy Beach:** If a Life Preserver is there, you get one (just one). See Section 5 for exit routes back onto the main path.

**Getting & losing preservers:**
- Earn one by bumping a player who has one, or by landing on a Life Preserver space.
- Lose one by getting bumped, or by landing on a (−1) space.
- Preservers lost to a (−1) space return to Crazy Beach.
- Players with no Life Preservers are unaffected by a (−1) space.

**⚠️ Life Preserver spaces:** When you land on one, you must first take a Life Preserver from Crazy Beach. If none are there, take one from another player.

## 13. Risky Rapids

- Any player on Crazy River may choose to enter the rapids. The only way back is the way you came.
- No exact roll needed to reach the shore space at the end — just enough to get there.
- Reaching the shore space earns a **Crazy Coin.**
- In tournament play, every player who reaches the shore space also earns a **Sand Dollar.** **See the companion Board Layout Reference** for the exact 9-space sequence from the Crazy River offshoot to the shore, including both (−1) spaces' positions.
- **Landing exactly on the shore always earns a fresh Crazy Coin** (and Sand Dollar, in tournament play) — regardless of how you got there (your own roll, a bump retreat, a swap) and regardless of whether you'd already collected one on this same trip through Risky Rapids. There is no such thing as a status that blocks a further coin; the only thing that matters is whether you land exactly on the shore space.
- **Bump retreat direction inside Risky Rapids depends on the bumped player's own current direction of travel — it's always backward relative to that direction, exactly like every ordinary bump on the board (Section 9's fixed-direction rule), and never influenced by the bumping player's own direction or position.** Because Risky Rapids is the board's only two-way corridor, "backward" genuinely differs depending on which way the bumped player is actually headed:
  - **Inbound** (still approaching the shore for the first time this trip, hasn't collected a coin yet): retreat moves them 2 spaces backward *toward Crazy River* — away from the shore, a genuine setback that costs them progress, same as any other bump on the board.
  - **Outbound / exiting** (already reached the shore this trip and is heading back toward Crazy River): retreat moves them 2 spaces backward *toward the shore* — away from Crazy River, sending them back deeper into the interior they were trying to leave.
  - **A player becomes "outbound" the instant they land exactly on the shore** — even before their next turn actually begins — and stays outbound until they fully leave Risky Rapids through the junction. **This status is used only to determine bump retreat direction; it has no bearing on coin eligibility**, which depends solely on landing exactly on the shore (the rule above) regardless of status.
  - This uses the same "own most recent movement" criterion already established generally in Section 9 — if it isn't already clear which way a bumped player is headed, ask them directly (e.g., "are you on your way to the shore, or already coming back from it?") rather than assuming from the bumping player's position.
- **Both ends of Risky Rapids can be reached by a retreat running out of room, but which end depends on direction, per the rule above.** Neither the shore nor the Risky Rapids junction space is a hard boundary — both are simply the functional ends of a single corridor with real, occupiable space connected on the other side. A bump retreat always applies its full 2 spaces; if it would run past the end it's headed toward, the leftover distance continues into whatever's actually connected there (space actions only trigger on final landing, never on being crossed mid-move, same as everywhere else on the board):
  - **Inbound player, retreating toward Crazy River, near the junction end:** if the retreat runs past the junction, the leftover distance continues out onto ordinary Crazy River track — the player is carried fully out of Risky Rapids for this attempt, no coin, and would need to make a fresh, deliberate choice to re-enter later if they still want to try for the shore (same as a first-time entry).
  - **Outbound/exiting player, retreating toward the shore, near the shore end:** if the retreat runs past the shore, the leftover distance continues back into Risky Rapids' interior (toward the junction) with the remainder — since there's no space beyond the shore in that direction, it wraps back the only way available.
  - **Worked examples:** An inbound player bumped exactly on the junction space (0 spaces from it) has their full 2-space retreat continue out into Crazy River. An outbound player bumped exactly on the shore space (0 spaces from it — this includes being bumped directly off the shore itself, since reaching the shore already makes them "exiting" even before their next turn) has their full 2-space retreat continue back into the interior. An outbound player bumped 1 space clear of the shore has 1 space of retreat reach the shore, with the remaining 1 space continuing past it into the interior — landing 1 space past the shore again, on the interior side, exactly where they'd have been anyway; this puts them right back in position to reach the shore again next turn and earn a fresh coin. An outbound player bumped exactly 2 spaces clear of the shore retreats exactly onto it — a fresh arrival, a fresh coin. Bumped 3+ spaces clear of the relevant boundary, in either direction, means no crossing occurs — the retreat simply lands short.
  - **Note — this replaces an earlier version of this rule that sent every bumped player toward the shore regardless of their own direction of travel.** That version had an unintended consequence: it meant a bump could actually help an inbound player (pushing them closer to a free coin) rather than punishing them, which doesn't fit how bumps work anywhere else on the board. The direction-dependent version above corrects that.
- **A Crazy Coin earned via a bump retreat is not revealed or resolved immediately — it waits until the start of that player's own next turn**, even though the retreat itself happens right away as part of resolving someone else's bump. This is a deliberate exception to the general rule that space actions trigger immediately even via a bump (stars, mud, and Life Preserver pickups all still resolve instantly): several Crazy Coins have effects that reach beyond the moment they're drawn (Take and Double's Life Preserver sweep, Surge's five-roll sequence) and resolving one mid-bump, during a different player's turn, would break turn order and create ambiguity about when those effects actually begin. The Sand Dollar (tournament play) follows the same deferred timing. **AI agent guidance:** If a player reaches the shore via a bump and asks whether they get their coin right away, the answer is no — they'll draw it at the start of their own next turn, not in the moment the bump happens.
- **Confirmed: Risky Rapids' interior is water for Life Preserver purposes.** Losing a last Life Preserver to a bump while inside Risky Rapids triggers the same immediate-sink sequencing already established for Crazy River and the whirlpools (Section 9).
- **Board layout note — a (−1) space sits exactly 2 spaces back from the shore,** meaning a player bumped directly off the shore lands squarely on it (per the wraparound rule above). The consequences depend heavily on their Life Preserver count at that moment:
  - **Holding exactly 1:** Gives it up to the bumper while still on the (dry) shore — no sink there. But the retreat then lands them on this (−1) space already holding zero Life Preservers, which sinks them on arrival (same principle as the Crazy River reconvergence worked example below) — they never actually land back in Risky Rapids at all, going straight to Crazy Beach instead. No coin either way, since they never completed a landing anywhere in Risky Rapids.
  - **Holding exactly 2:** Gives one to the bumper (1 left, still fine on the dry shore). The (−1) space's own action then costs their last remaining Life Preserver — losing it while standing on a water space triggers the standard sequencing sink (Section 9). Same result: Crazy Beach, not Risky Rapids, no coin.
  - **Holding 3 or more:** Survives both hits with at least 1 remaining. Lands on the (−1) space and simply continues their exit on their next turn — no coin from this bump, just a shorter remaining exit.

- **A swap changes only physical position, never a player's own inbound/outbound status.** Status tracks the player's personal trip history (have *they* reached the shore this attempt), not which space they happen to occupy — so swapping into the middle of Risky Rapids doesn't retroactively count as having reached the shore, and swapping out of it doesn't erase progress already made. (The reverse case — repositioning a player who's already inside Risky Rapids to another spot still inside it — needs no separate rule at all: nothing was removed, so nothing about their status changes. This requires both swap participants to already be inside the same short corridor at once, which is rare enough not to be worth a dedicated case.)
  - **A player swapped into Risky Rapids from elsewhere on the board** (they weren't already inside on their own steam) starts as **inbound**, exactly like a fresh entry — regardless of which specific interior space they land on, even one deep enough that the player they swapped with was themselves outbound. If later bumped from that position, their retreat goes toward Crazy River (the inbound direction), not toward the shore, even though the space itself is "close to the shore."
  - **A player swapped out of Risky Rapids entirely** (onto some other part of the board) simply leaves that attempt unresolved, in whatever state it was — inbound or outbound, no coin from it either way. A fresh, deliberate re-entry is required to try again, same as being forced out via a bump retreat past the junction. **This also applies to any full removal generally** — sinking, or being pushed out past the junction by a bump retreat, end an attempt exactly the same way. A player who left Risky Rapids by any of these means and is elsewhere on the board later isn't "already inside" if they end up back there — that's a brand-new attempt, starting inbound, no matter how they got there or what their status was before they left.

**Strategic note (for richer player-facing answers, not mechanical rules):** Risky Rapids is meant to be genuinely tempting, not just technically optional — it's the board's biggest risk/reward swing, and the Crazy Coins earned there can decisively shift a game (see Section 14's full list). Without anyone using one, games can run long, so when a player asks whether it's worth attempting, lean into real enthusiasm about the reward rather than a neutral "both are fine" framing. But stay honest about the downside — don't minimize it to make the pitch cleaner. The realistic worst case is losing Life Preservers along the way, and if a player runs out entirely while inside, sinking all the way back to Crazy Beach, which is a genuine setback. That's a real risk, not a guaranteed outcome, and it's exactly what makes the reward worth having — an honest, complete picture of both sides is more persuasive than a softened one, and it means a player who does draw a bad outcome doesn't feel like the assistant undersold the risk to talk them into it. **AI agent guidance:** Apply this enthusiasm only to genuinely open strategic questions ("is it worth it," "should I risk it," "why would I go in there") — don't inject unprompted hype into purely mechanical rulings (a bump-direction question, a coin-timing question) that have nothing to do with whether to attempt Risky Rapids at all.

## 14. Crazy Coins

Powerful, stackable advantages, drawn when a player reaches the Risky Rapids shore. **If the shore is reached via a bump retreat rather than the player's own roll, the coin is drawn at the start of that player's own next turn, not immediately (Section 13).**

- **Swap:** Hold this coin. **The earliest it can be used is your next turn — never the same turn you drew it.** You draw this coin as the resolution of the roll that got you to the Risky Rapids shore; that roll is already spent for this turn, and using Swap means using your *entire* turn instead of rolling (see below), so there's no roll left this turn to substitute. From your next turn onward, you can play it whenever you choose: instead of rolling, swap places with any player. **Mirrors the board Swap space exactly:** if that player has a Life Preserver, you take it from them, and you must complete the action on the space you swap to. **AI agent guidance:** If a player asks whether they can use a just-drawn Swap coin immediately, the answer is no — be direct about this rather than defaulting to "the timing is entirely up to you," which is true of *when* to eventually use it but not of using it on the very turn it was drawn.
- **Take and Double:** Take ALL Life Preservers from Crazy Beach and other players (players currently in water must go to Crazy Beach). Then double all your rolls until you reach **Sharky Shores.**
- **Easy Win:** Exact roll not needed to win. If you draw a second Easy Win coin, you must give it to another player.
- **Surge:** Activates immediately. All other players freeze while you roll 5 times in a row, doubling each roll. Ignore all action spaces except Life Preserver spaces. If your final surge roll lands on a bad space, you must follow its rule.
- **Double Fours & Fives:** Roll a 4 or 5? You may double it if you want. This coin is yours for the rest of the game.
- **Bonus Golden Life Preserver:** Put on the golden bonus Life Preserver. It cannot be taken until you reach **Sharky Shores** — then it functions like any other preserver. This protection is universal — it blocks bumps, swaps, and Take and Double alike, not just one specific mechanic. **Sharky Shores is the only approach to the Castle** — there's no other segment of the board that connects to it (see the companion Board Layout Reference), so a player close enough to the Castle to be asking about landing on it exactly is, by definition, already in Sharky Shores. **AI agent guidance:** If a conversation has already established that a player is near the Castle — discussing an overshoot roll, a small exact roll needed to win, etc. — and they then ask whether their Golden Life Preserver is still protected, answer definitively using that context ("you're already in Sharky Shores at this point, so it's no longer protected — normal rules apply") rather than restating the general rule conditionally as if their location were still unknown.

**Coin lifecycle — three states, not a simple reshuffle:**
- **Held coins (while unused)** stay with the player and are never part of any reshuffle: **Swap** (held only until the player chooses to execute it — once used, it moves to the discard pile like any other resolved coin, it is not a permanent hold), **Double Fours & Fives** (kept for the entire game, never discarded), and **Easy Win** (kept for the entire game unless a second copy forces a hand-off to another player).
- **Not all "held" coins work the same way when it comes to using them.** Swap is an *active* choice — a player uses their whole turn (instead of rolling) to execute it, exactly like the board Swap space, and the earliest that can happen is their next turn (see Section 14's Swap entry — the turn it's drawn on is already spent). Double Fours & Fives and Easy Win are *passive, standing abilities* — they don't consume a turn to "use." Double Fours & Fives just applies automatically whenever a 4 or 5 comes up on any normal roll; Easy Win is a permanent modifier to the win condition with no activation moment at all. Don't describe either of these as something a player "waits for their turn to use" — only Swap works that way.
- **Used coins** are set aside in a discard pile once resolved — they do **not** go back into the draw stack right away: **Surge** (resolves immediately upon drawing), **Take and Double** (its Life Preserver-taking effect is instant; the lingering doubling is tracked as a status, not tied to the physical card), **Bonus Golden Life Preserver** (converts into a board token, not an ongoing card ability), and **Swap** (once actually executed — before that, it's held).
- Once the draw stack itself runs out (very rare), the discard pile is shuffled and becomes the new stack. Coins still actively held (Double Fours & Fives, Easy Win, or an unused Swap) are never included in this reshuffle, since they haven't left player hands.

**Strategic notes (for richer player-facing answers, not mechanical rules):**
- **Double Fours & Fives** is valuable specifically because doubling is optional — a player can dodge a roll that would land on a negative space, aim for a positive one instead, or in some cases land an exact winning roll on the Castle by doubling a 5.
- **Swap** is powerful both offensively and defensively — it can propel a player straight toward the end when conditions are right (a good target player, favorable Life Preserver count), or be used purely to stop another player from winning. One especially strong combo: swapping with a player stuck in a Sharky Shores whirlpool who's holding at least one Life Preserver — the swapper steals that Life Preserver and lands in a strong position near the Castle.

## 15. Tournament Play

- **Earning Sand Dollars:** Conquer Risky Rapids → 1 Sand Dollar. Win a game → 3 Sand Dollars.
- **Winning the tournament:** First player to the required Sand Dollar count wins.
- **Crazy Coins reset each game.** Held coins (Swap, Double Fours & Fives, Easy Win) do not carry over from one tournament game into the next — the Crazy Coin stack is freshly shuffled at the start of every new game, same as Setup (Section 2). Only Sand Dollars persist across the tournament.

## 17. Consolidated Edge Cases

**Game Mechanics**
- *All players stuck in Mud on consecutive turns* → Lost turns cancel out; continue as normal.
- *Player bumped at a crossroads with more than one path back* → See Section 9 — retrace the exact path just traveled, never a new choice.
- *Player bumped off a mud space, whether or not they'd already retrieved their die* → Any pending obligation clears immediately — they retrieve their die (if it was still in the puddle) and continue play normally from their new position 2 spaces back. Leaving the mud space clears the obligation regardless of how they left it.
- *Player bumped to a star and takes their free turn* → Per the general turn-order principle (Section 3), the next turn goes to the player after the one who just rolled — which here is the bumped player, since their star roll was the most recent turn taken. This is not a special bump rule; it would be true of any player landing on a star by any means.
- *Player bumped to a plain space with no bonus action* → No extra roll happens, so nothing changes about whose turn was "last" — the bumping player is still the most recent one to have taken a turn. Play proceeds normally to the player after the *bumping* player, exactly as it would have if no bump had happened at all.
- *Player bumps someone stuck in an escape box* → The bumped player is freed (retreats 2 spaces per Section 9, no longer occupying the box) but the bumping player is now stuck in the escape box in their place — landing there traps whoever's standing on it, bumper included. See Section 3.

**Swaps**
- *Player lands on a Swap space* → Must swap, even at a disadvantage. **Takes a Life Preserver from the other player if they have one.**
- *A swap lands a player in water with zero Life Preservers* → **This cannot actually happen, and this entry is corrected accordingly.** The only way a swap lands a player in water at all is by swapping into the position of a player who is themselves currently standing in that water hazard — and per Section 12's water invariant, that player is always holding at least one Life Preserver (a player in water with zero would have already sunk). So the incoming swapper always receives a Life Preserver as part of the transfer and lands safely; there's no scenario where "neither player had one to transfer" while one of them is already in water.
- *Player swaps with someone standing in Risky Rapids, Crazy River, or a whirlpool* → The Life Preserver "if they have one" language (Section 10) isn't really conditional here — per the water invariant (Section 12), a player already in water is guaranteed to hold one. The swapper takes it and lands safely; there's no need to ask about either player's Life Preserver count before answering.
- *Player swaps with someone at the Risky Rapids shore space* → Must complete that space's action and receives the next available Crazy Coin (and Sand Dollar, in tournament play) — but per Section 13's coin-timing rule, the coin is drawn at the start of their own next turn, not at the moment of the swap. Standard Life Preserver transfer rule still applies (and per the water invariant, the player being swapped is guaranteed to have one).

**Life Preservers**
- *A player lands on another player AND a Life Preserver space simultaneously* → Take two: one from the bumped player, one from Crazy Beach (or any player if Beach is empty).
- *Player with only one Life Preserver is bumped while in water* → No moving back — they immediately lose their preserver and go ashore at Crazy Beach.
- *Player loses their last Life Preserver in Risky Rapids via a (−1) space* → Preserver goes to Crazy Beach; player goes there too and picks it back up.
- *Another player lands on Crazy Beach where a player already is* → No bump. Crazy Beach is the only space where multiple players can coexist. **Each player who actually arrived by sinking (or a qualifying Tournament Mode start, Section 16) gets their own Life Preserver pickup independently**, per the standard re-entry rule (Section 5) — one player's presence or pickup has no bearing on another's. If a Life Preserver is available when the second player re-enters, they get one too, exactly as the first player did. **AI agent guidance:** This is a direct consequence of the scenario, not a separate follow-up topic — per the answer-structure principle (top of document), state it in the same answer as the no-bump explanation rather than waiting for the player to ask "does the other person get one too?" Also, don't hedge on *how* the second player arrived unless there's an actual reason to think otherwise — Crazy Beach is entry-only (Section 5), so if two players are both standing there, both arrived by sinking (or a Tournament Mode start) by definition; there's no other way to be there.
- *Player with no Life Preservers bumps someone on a (−1) space who has one* → Take one preserver as usual, then follow the (−1) action — lose it and go to Crazy Beach.
- *Player barely inside Crazy River with only one Life Preserver gets bumped* → Loses the Life Preserver first (proximity handover, since both players share the same space), immediately sinks because they're still standing in the water, and re-enters at Crazy Beach. The 2-space retreat never happens — sinking overrides it.
- *Player sitting on the first of the 3 whirlpools with only one Life Preserver gets bumped* → Same sequencing: loses the Life Preserver first, immediately sinks since they're still on the whirlpool, and re-enters at Crazy Beach instead of retreating.

**Risky Rapids**
- *Player lands on another player already at the shore space* → Standard bump: the player at the shore is "outbound" the instant they landed there (Section 13), so their retreat direction is toward the shore — which, from the shore itself, means wrapping immediately into the interior (deeper into Risky Rapids, per Section 13's wraparound). Since they're now the ones who most recently returned from this exact spot, a further bump partway back toward shore would still count as continuing this same exit.
- *Bumped player at the shore space has no Life Preserver* → Cannot survive in the water; must be rescued to Crazy Beach immediately.
- *Player returns to the shore space by any other means (swap or bumped back)* → Counts as a brand-new arrival — collect the next available reward at the start of their own next turn (Section 13's coin-timing rule), regardless of whether they'd already collected one earlier on this same trip.
- *Player still approaching the shore for the first time this trip (inbound) gets bumped* → Retreat moves backward *toward Crazy River*, away from the shore (Section 13's direction rule) — this is a genuine setback, not a boost toward the shore. If the retreat carries them past the junction, they're pushed fully out into ordinary Crazy River, no coin, and would need a fresh, deliberate re-entry to try again.
- *Player is partway back into Risky Rapids on the return trip toward Crazy River (outbound) and gets bumped* → Retreat moves backward *toward the shore* (Section 13's direction rule), deeper into the interior. If this lands them exactly on the shore space, it's a brand-new arrival and they collect a fresh coin at the start of their next turn — this is true no matter how many times it happens on the same trip. If it doesn't land exactly on the shore, no coin this time, and their next turn simply resumes heading back out toward Crazy River from wherever the retreat left them.
- *Player at the Risky Rapids junction space, having just returned from the rapids, gets bumped* → Retreats 2 spaces back into Risky Rapids, retracing their own most recent path — not backward along Crazy River. If this lands them exactly on the shore, it's a fresh arrival and a fresh coin (Section 13) — there's no status that blocks this. A player arriving at that same junction space via normal forward Crazy River movement (not fresh off a rapids run) retreats along Crazy River instead, with no interaction with Risky Rapids at all.
- *Player already exiting, several spaces clear of the junction on ordinary Crazy River, gets bumped* → If their own most recent movement was exiting Risky Rapids, the retreat continues along that same corridor and can cross back through the junction into Risky Rapids' interior if the leftover distance reaches that far — same underlying "retreat is backward along your own established direction" principle, just playing out on the Crazy River side of the junction rather than inside Risky Rapids itself.

**Crazy Coins**
- *Surge player's final roll lands on a negative space* → Must follow the action on that space.
- *Player with "Take and Double" rolls, lands on an escape box* → Still roll one of the two escape numbers, but double that roll amount.
- *Player using "Take and Double" then draws a Surge coin* → Surge activates immediately — all rolls doubled, negative spaces ignored (except Life Preserver spaces). If Surge carries past **Sharky Shores**, Take and Double expires. If not, doubling continues after Surge ends.
- *Player holding Double Fours & Fives also has Take and Double active (stacked)* → Take and Double's blanket doubling takes precedence for the duration of its window — a roll of 4 or 5 is doubled once, not compounded by both effects. Double Fours & Fives isn't consumed or lost; it simply has nothing extra to contribute while Take and Double is active, and should resume being the player's option on future 4/5 rolls once Take and Double's doubling window ends at Sharky Shores.
- *Player draws Take and Double while another player holds the Bonus Golden Life Preserver, not yet at Sharky Shores* → The Golden Life Preserver is protected by its own explicit rule and cannot be taken. Take and Double's "take all" action happens once, immediately upon drawing — no retroactive taking later, even if the golden preserver's holder reaches Sharky Shores afterward while the doubling window is still active. The only way it gets swept up is if its holder had *already* reached Sharky Shores before Take and Double was drawn, since it's already functioning as a normal preserver by then. **AI agent guidance:** Keep the default answer to just "it's protected until they reach Sharky Shores; the only way to get it is if they've already reached it" — don't proactively explain the one-time/no-retroactive-taking nuance. That's a follow-up-level detail most players won't think to ask about; only bring it up if someone specifically asks what happens if the holder reaches Sharky Shores *during* an active doubling window.
- *Player swaps with someone holding the Bonus Golden Life Preserver, not yet at Sharky Shores* → The golden preserver doesn't transfer — same universal protection as with Take and Double. If the swapee also holds a regular Life Preserver, that one transfers normally per the standard swap rule; the golden one stays with them regardless until they reach Sharky Shores.

## 18. Side Notes — Additional Resolved Scenarios

Scenarios resolved through direct Q&A that don't fit the terse "if X then Y" format of the Consolidated Edge Cases above, but are fully confirmed and carry equal authority.

- *Player lands on a Risky Rapids (−1) space with only one Life Preserver* → Loses the Life Preserver (it goes to Crazy Beach), then immediately sinks since they're now in water with zero Life Preservers, re-entering at Crazy Beach — where they immediately reclaim the very Life Preserver they just lost, per the standard Crazy Beach re-entry rule (Section 5).
- *Player lands on another player who is standing on a Life Preserver space* → Gets two Life Preservers from that single move: one from the bump (if the other player has one), and one from the space itself (Crazy Beach, or another player if Beach is empty). The two sources are independent — if the bumped player has none to give, the bumper still gets exactly one from the space.
- *A Life Preserver arrives at Crazy Beach mid-game (e.g., another player loses one there via a (−1) space) while a different player is already sitting at Crazy Beach waiting for their next turn* → The waiting player does **not** get it. The "take a Life Preserver" rule is tied to the act of *re-entering* Crazy Beach after sinking, not to merely being present when one becomes available. That Life Preserver stays there for whoever next actually sinks and re-enters — not for a player who was already sitting there beforehand.

40. **Risky Rapids bump/coin rules substantially reconciled** (Section 13, Section 17) — a design discussion, not a live-agent error, but one that surfaced a genuine internal contradiction the agent's earlier accurate-sounding answers had been quietly built on top of. The old rule said reaching the shore permanently flips a player to "exiting" status, and a bump can never grant a further coin once that status is set — but a worked example a few lines later, for a bump landing a partly-exited player back on the shore, said the opposite: "a brand-new arrival, coin earned immediately." These directly contradicted each other. Resolved in favor of the simpler, unified rule: **landing exactly on the shore always earns a fresh coin, regardless of status or how the player got there** — this removes an entire special-case rule rather than adding one. Also added: the shore's existing "retreat wraps around when it runs out of room" behavior is now applied symmetrically at the Risky Rapids junction end too, so a bump can carry an exiting player back into Risky Rapids' interior with leftover retreat distance, exactly as it already could at the shore end — this was raised as a specific scenario and requires no separate boundary or exception, since it falls out of the same distance-based logic already governing the shore. **New rule added:** a Crazy Coin earned via a bump or swap (rather than the player's own roll) isn't drawn until the start of that player's own next turn — several coins have effects that extend beyond the moment they're drawn (Take and Double, Surge), and resolving one mid-bump during a different player's turn would break turn order. **Self-caught error during drafting:** an early draft of this fix mistakenly reworded the bump-direction rule to send an already-exiting player's retreat further toward Crazy River (in their current direction of travel) rather than back toward the shore — this was caught and corrected before being shown, since it directly contradicted the scenario that prompted this whole discussion. The retreat direction itself was never actually in question and remains unchanged: always toward the shore, regardless of the bumped player's entering/exiting status, and never influenced by the bumping player's own position. Several Section 17 edge cases referencing the old contradictory language were updated to match.
41. **Bump-chain fork ambiguity — cross-referenced to the existing clarifying-question pattern instead of a vague generic disclaimer** (Section 9) — not a new rule needed, but a guidance-application gap. A live transcript described a two-player bump chain (bumping someone who retreats onto a second player); the agent handled the mechanics correctly but closed with a vague, catch-all disclaimer about forks and "tricky spots" possibly being involved, offering to explain further if asked. Section 9 already has a well-built pattern for exactly this ambiguity two bullets up — the "asking the right clarifying question" guidance, which deliberately avoids naming forks abstractly (since the board's forks don't visually read as forks to players) and instead asks a concrete, plain-language question. The agent didn't apply that pattern to the cascading case; it fell back to generic jargon instead. Added a cross-reference making explicit that each hop in a bump chain is an independent bump for this purpose, and explicitly prohibited the vague "let me know if it's a tricky spot" style disclaimer — the agent should either ask the same concrete question already modeled, or say nothing about it if nothing suggests it's relevant, rather than hedge with unrecognizable terminology.
42. **Risky Rapids bump-retreat direction corrected to depend on the player's own travel direction — partially reverses item #40.** Item #40 had explicitly settled on "always toward the shore, regardless of status" for retreat direction, reasoning that direction and coin-eligibility should be decoupled. That coin-eligibility conclusion was right and stands unchanged: landing exactly on the shore always earns a coin, no exceptions. But the direction conclusion had an unintended consequence, caught through a design discussion prompted by a live scenario: a bump could actually *help* an inbound player by pushing them toward the shore (and potentially straight onto it for a free coin) rather than punishing them — which doesn't fit how a bump works anywhere else on the board. Corrected: retreat direction is always backward relative to the bumped player's own actual direction of travel, exactly like the general Section 9 principle — an inbound player (still approaching the shore for the first time this trip) retreats toward Crazy River; an outbound/exiting player (already reached the shore, heading back) retreats toward the shore. This required also reworking the wraparound logic: an inbound player's retreat can now carry them fully out of Risky Rapids into ordinary Crazy River if it overshoots the junction, and an outbound player's retreat wrapping past the shore continues into the interior exactly as before (that half was already correct and unchanged). A player becomes "outbound" the instant they land on the shore — this status now matters again for direction, even though item #40 correctly removed its relevance to coin eligibility. Section 13's core rule and all affected Section 17 edge cases were rewritten to match.
43. **Swap interactions with Risky Rapids' inbound/outbound status clarified** (Section 13) — a genuine gap surfaced by the direction fix in item #42, not a live agent error. Once retreat direction started depending on a player's own inbound/outbound status, a new question followed naturally: does swapping a player into or out of Risky Rapids affect that status? Resolved by extending an already-established principle rather than making a new design call: status tracks the player's own trip history (have they personally reached the shore this attempt), not the physical space they occupy, so a swap — which only relocates a player — can't change it. A player swapped into Risky Rapids from elsewhere starts inbound regardless of how deep into the corridor they land; a player swapped out of Risky Rapids entirely simply leaves that attempt unresolved, same as being forced out by a bump retreat past the junction. **Follow-up trim, same session:** the original draft gave repositioning a player already inside Risky Rapids (via a swap that keeps them inside) its own separate worked-out case, including a worked example distinguishing it from a full removal like sinking. On review, that case needs both swap participants to already be standing inside a 9-space corridor at once — genuinely rare, with little strategic upside — and it added no new information beyond what the general principle right above it already implies (nothing removed, so nothing about status changes). Compressed it to a brief parenthetical rather than a dedicated bullet, and folded the sinking/full-removal clarification into the "swapped out" bullet instead, where it fits more naturally as one instance of a general rule rather than a special case of its own.
44. **General guidance added: lead with a direct yes/no, don't open with a false hedge** (top of document) — caught via a live AI agent transcript, and the first entry from a dedicated pass reviewing answers for over-explanation rather than factual errors. A player asked a clean yes/no question (does landing on a whirlpool cost a Life Preserver) and the agent opened with "Not exactly... the whirlpools don't cost you a Life Preserver directly" — the actual answer is simply "no," full stop; a Life Preserver isn't consumed by landing there at all. The word "directly" wrongly implied some indirect mechanism that doesn't exist, manufacturing a nuance that wasn't there and making a simple mechanic sound more complicated than it is. This is a general phrasing failure mode, not specific to whirlpools, so added as a fourth general AI agent guidance note alongside the existing three (table formatting, answer structure, context resolution): give the plain yes/no first, and reserve hedges like "not exactly" or "technically" for cases with an actual partial truth to convey.
45. **General guidance added: name the Life Preserver's purpose in safe-outcome explanations, don't just say "nothing happens"** (top of document) — the second entry from the over-explanation review pass, though this one adds rather than trims. A player with a Life Preserver landed on a whirlpool and asked what happens; the agent's answer was accurate ("nothing bad happens... your count doesn't change") but flat — it described the safe outcome without naming why it's safe. Unlike the other guidance notes in this pass, which remove hedges and unrelated caveats, this one deliberately keeps an answer from being *too* terse: the Life Preserver's entire purpose is surviving water hazards, and when it's actively doing that job, saying so ("you're safe — that's exactly what it's for") reinforces the core mechanic instead of treating survival as a default. Added as a fifth general AI agent guidance note, explicitly distinguished from the trimming-focused notes above it.
46. **Response-format guidance tightened to close a bulleted-list loophole** (top of document) — third entry from the over-explanation pass, and not a new principle, just closing a gap in an existing one. A player made an offhand observation about having a choice at Crazy Beach's exit; the agent confirmed the choice correctly but then volunteered a full roll-by-roll breakdown of both routes as a bulleted list — nobody asked for it, and the existing "don't reproduce a table in chat" guidance (item #1 in this list) technically only mentioned literal markdown tables, leaving room to read a bulleted enumeration of the same data as compliant. It isn't: the problem was always completeness, not table syntax. Reworded to state explicitly that converting a table to a bulleted list doesn't exempt it from the same guidance, and added this exact scenario as a concrete example.
47. **Two issues from one transcript: unprompted hypothetical caveat, and redundant restating of already-settled information** (top of document, both the answer-structure guidance and a new sixth note) — fourth and fifth entries from the over-explanation pass. A multi-turn Portal/bump conversation ended with an answer that (a) mentioned "if anyone's sitting on the destination Portal space, standard bump applies" when nothing in the conversation indicated another player was there — a hypothetical branch for an unconfirmed scenario, not a consequence of the one described — and (b) recapped the player's own just-given account of rolling a 2 and getting bumped back as numbered steps, and restated the "Portals always trigger, no exemption" rule that had already been fully explained one turn earlier. Fix (a) added a concrete example to the existing answer-structure guidance (item #2 in this list), since the underlying principle already covered this but didn't have an example clarifying that *hypothetical, unconfirmed* branches count as "doesn't apply to the scenario," same as confirmed-irrelevant ones. Fix (b) is a genuinely new principle, added as a sixth general guidance note: don't hand a player's own account back to them as an explanation, and don't re-teach a rule already fully stated earlier in the same conversation — a brief confirmation covers it the second time.
48. **Terminology fix: "walk"/"walked" replaced with "travel"/"traveled" throughout** — caught when a live answer used "walk" to describe movement through Crazy River, which reads oddly for a water hazard nobody's literally walking through. Swept the whole document: 8 instances in active rules text changed (Sections 3 and 9, largely the Star and forward-movement rules), while historical changelog entries were left as-is since they're a record of what was true to say at the time, not active guidance. Added as a seventh general guidance note for consistency going forward, with an explicit carve-out for "walk through" used as an ordinary English idiom for explaining something step by step — that's unrelated to board movement and wasn't the problem.
49. **General guidance added: never say internal Smiley/Frowny numbering ("Frowny 1," "Smiley 4") to a player** (top of document) — caught via a live AI agent transcript, where a bumped player was told they'd been sent to "Frowny 1's destination." That numbering is purely an internal documentation convention (see the companion Board Layout Reference's own legend: "independently numbered per type") for keeping this document organized — it was never printed on the physical board or meant to be player-facing, but nothing had ever said so explicitly, which is exactly how it leaked into a live answer. Added as an eighth general guidance note: describe a Smiley or Frowny by what's actually visible (its physical location) or by its effect (the destination in plain terms) — never by its internal reference number. The one place the numbering legitimately still appears, Section 3's distance-examples note, was left unchanged since that's internal documentation for keeping edits consistent, not agent-facing output.
50. **Free turns clarified as always purely additive, never substitutive for a player's own future turn** (Section 3) — a subtle but genuine correctness issue caught in a live transcript, not a design question. A player was bumped onto a star by the player directly before her in seating order; the agent correctly said she wasn't getting two rolls stacked back-to-back and that play moves to the next player after her — both right. But its closing summary said the free turn "landed exactly on what would've been your normal turn anyway... taken via the star instead of a fresh roll from wherever you'd have started," implying the free turn substituted for her regular turn rather than being an addition to it. Tracing the rotation forward shows this is wrong: a free turn never removes or delays a player's own natural turn later in the rotation — it's always a genuine extra roll layered on top. The appearance of coincidence here was purely an accident of seating (the bumping player happened to sit directly before the bumped player), and the same framing would visibly break for a bump from any other seat. Added an explicit rule stating free turns are always additive, with this exact scenario worked through as the example, plus guidance that "do I get two turns" deserves a nuanced answer (no back-to-back stacking, but yes to one genuine extra roll overall) rather than a flat no.
51. **Strategic encouragement added for Risky Rapids** (Section 13, cross-referencing Section 14) — a design request, not a correctness fix. The live agent's answer to "why would I risk Risky Rapids" was accurate and balanced but neutral, treating attempting it and skipping it as equally valid without leaning into how genuinely strong the reward is — and without a coin in circulation, games can run long. Added a strategic note instructing the agent to answer open strategic questions about Risky Rapids with real enthusiasm about the payoff. **Pushed back on and revised one specific piece of the request:** the proposed phrasing framed the downside as minor ("knocked back a little ways"), which isn't accurate — running out of Life Preservers inside sinks a player all the way back to Crazy Beach, a genuine setback established elsewhere in this document. Softening that to make the pitch cleaner risks a player feeling misled by the rules assistant itself the first time they draw a bad outcome. The note instead pairs genuine enthusiasm about the reward with honesty about the real risk, on the reasoning that an honest complete picture is more persuasive than a softened one. Scoped narrowly: this applies only to genuinely open strategic questions, not to mechanical rulings that happen to involve Risky Rapids.
